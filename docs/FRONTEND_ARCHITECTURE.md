# Architecture frontend (web/)

Application React 19 + TypeScript construite par Vite, stylée avec Tailwind 4, état géré par Zustand. Elle tourne dans la WebView2 unique de l'hôte et porte toute l'interface : arborescence des workspaces, onglets, splits, terminaux xterm.js, Leader et palette.

## Structure

| Dossier | Rôle |
| --- | --- |
| `src/model/` | Modèle de session pur (types, fabriques, helpers d'arbre `panesOf`, `replaceNode` (rend le même nœud quand rien ne change dans un sous-arbre), `pruneNode`, `splitLeaf`, `setRatioAt` (chemin `SplitPath` de côtés `SplitSide`, ratio borné par `clampRatio`), `equalizeNode` (répartit chaque split selon le nombre de panes alignés de chaque côté dans sa direction, pour « Égaliser les panes »), `swapPanes` (échange deux feuilles sans toucher aux ratios, pour « Échanger avec le voisin »), `tabOfPane` (onglet d’un seul pane existant, pour « Déplacer dans un nouvel onglet »), sélecteurs `activeWorkspace`, `activeTab`, `activePane` ; un onglet et un pane créés par un agent portent `owner`, le pane de cet agent (fabriqués par `createOwnedPane`, `createOwnedTab`, `createOwnedWorkspace`, retirés d'une copie par `disownTab`) ; un onglet porte `explorer` (panneau de droite ouvert) et `panel` (`RightPanelView` : Fichiers, Git ou Notes, Fichiers si absent), un workspace `note` (texte brut, absente si vide, au plus `NOTE_MAX_CHARS` caractères, reprise par l'onglet fermé qui était son dernier dans `workspaceNote` ; `notePreview` en donne la première ligne non vide, tronquée à 80 caractères), la session `explorerWidth` (largeur du panneau de droite) et `gitGraph` (`GitGraphLayout` : largeur et ouverture de la colonne des branches, largeurs des colonnes du graphe, affichage d'Auteur et de Date, bornés par `clampGitGraph`)). | `src/browser/` | Panes navigateur (section 7 de la spec, « Panes navigateur »). `model/browser.ts` porte `PaneKind.Browser`, `BrowserViewport` (desktop, mobile), `pageName` (nom d'onglet : titre, sinon hôte) ; un `Pane` navigateur garde `kind`, `url` et `viewport` en plus du dossier et du shell du pane d'où il a été ouvert (`createBrowserPane`, `isBrowserPane`, `paneName`). `browserLayer.ts` : boucle `requestAnimationFrame` démarrée par `App` qui, pour chaque corps de pane navigateur affiché (`[data-browser-body]`), envoie `browser.attach` à la première apparition (adresse, largeur, lettres de `DIRECT_LETTER_KEYS` à intercepter dans la page), puis `browser.bounds` quand son rectangle change, et `visible: false` pour un pane retiré du DOM (autre onglet, autre workspace, pane agrandi ailleurs). Il fige la page quand un menu, un dialogue ou la palette est ouvert (`[role=menu]`, `[role=dialog]`, `[role=alertdialog]`), qu'une infobulle chevauche le pane, ou qu'un autre élément recouvre l'un des 16 points échantillonnés par `elementFromPoint` : capture `browser.snapshot`, image affichée dans le corps du pane, puis vue masquée une fois l'image chargée (`snapshotShown`) ; à la fin, vue réaffichée et image retirée 150 ms plus tard. `disposeMissingBrowsers` ferme la vue des panes sortis de la session ; `focusBrowser` / `restoreBrowserFocus` rendent le focus à la page du pane actif (après un raccourci renvoyé par la page ou la fin du Leader, si rien d'autre n'a pris le focus). `browserRequests.ts` : `requestBrowser` numérote une commande `browser.*` (numéros de `requestListeners`) et attend son `browser.reply`. `browserActions.ts` : `openBrowser` (côte à côte, en dessous ou en onglet, page vide et champ d'adresse en édition), navigation, Précédent, Recharger, largeur (enregistrée dans la session), DevTools, et réception de `browser.state` (adresse et nom d'onglet dans la session), `browser.newPane` (nouveau pane côte à côte), `browser.focused` (pane actif), `browser.failed`. `browserKeys.ts` : `browser.key` → `handleForwardedKey` de `shortcuts.ts` (Leader, Ctrl + P, raccourcis directs, Alt + F4) après avoir retiré le focus de l'élément actif. |

## Flux

1. `App` envoie `app.ready` ; l'hôte répond `app.hello` avec la session persistée (ou initiale), les shells disponibles, le texte des panes de la session précédente et les réglages de persistance. Le texte est injecté dans chaque pane avant le premier attachement ; un message `recovery` s'affiche en avertissement quand un fichier a été mis en quarantaine.
2. `sessionStore.load` charge la session ; `SplitView` rend l'arbre de l'onglet actif ; chaque `TerminalPane` demande `terminal.create` à son premier attachement.
3. Toute mutation du store produit une nouvelle session par partage structurel (Immer : objets non modifiés conservés, session produite figée, jamais de mutation en place) ; `App` la sauvegarde après 500 ms de calme via `session.save` et détruit les terminaux dont le pane n'existe plus (le texte est alors renvoyé pour purger `text.json`). Le texte des terminaux part indépendamment toutes les 30 s (seuls les panes modifiés ; l'historique déjà sérialisé est réutilisé, le reste l'est par tranches pendant les temps morts) et à la fermeture ; un échec d'écriture affiche « Non enregistré » dans le pied de page jusqu'à la prochaine écriture réussie.
4. `terminal.cwd` (émis à chaque prompt) met à jour `pane.path` et efface un éventuel état local du pane ; quand ni le dossier ni le nom automatique de l'onglet ne changent, la session n'est pas modifiée : aucun rendu ni aucune sauvegarde ; le nom automatique de l'onglet, le contexte Git et les actions de dossier suivent ce chemin, ce qui couvre `wtr`. `terminal.pathMissing` (après `rmwt` ou au démarrage) marque le pane comme dossier disparu sans le fermer. `terminal.output` va directement à l'instance xterm.js sans passer par React.

## Règles

- Le modèle et le pont ne connaissent pas React. Les composants ne contiennent pas de logique métier : ils appellent les actions du store.
- Les handlers sont des fonctions nommées (`handleSelect`, `handleClose`), pas de lambdas inline avec logique dans le JSX.
- Enums TypeScript plutôt que types union pour les valeurs fermées (`SplitAxis`, `StatusLevel`, `Renderer`). `erasableSyntaxOnly` est désactivé pour cela.
- Couleurs via les tokens `tily-*` de `index.css`, jamais en dur dans les composants. Le thème xterm.js est centralisé dans `terminalRegistry`.
- Textes visibles en français. Les termes Git restent en anglais et invariables, employés comme des noms : Push, Pull, Fetch, Stash, Stage / Unstage (Staged / Unstaged), Merge, Rebase, Amend, Checkout, Cherry-pick (« Push vers origin/main », « Faites un pull »).
- Fichiers de moins de 400 lignes, un composant exporté par fichier.

## Commandes

```
cd web
pnpm install
pnpm dev        # serveur Vite sur http://localhost:5173, à combiner avec TILY_WEB_DEV_URL côté hôte
pnpm build      # tsc -b puis vite build vers web/dist
pnpm lint       # oxlint
```

Aucun test web pour l'instant (décision du 21 septembre 2026) ; le modèle est validé côté hôte par `SessionValidator` et ses tests xUnit.
